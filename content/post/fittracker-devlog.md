## 当前进度

FitTracker 是一个运行在 HarmonyOS 上的健身训练记录应用。它的目标不是只做一个动作列表，而是把“设定目标 -> 生成计划 -> 执行训练 -> 复盘记录 -> 调整下次安排”串成一个能每天使用的闭环。

截至 2026 年 6 月 9 日，项目主线功能仍然大约完成到 `98%`，已经进入 `Phase 4`。现在的重点不再只是补页面，而是补齐内容同步、长期演进能力和发布前底座。

```text
Phase 1 基础训练闭环            100%
Phase 2 内容与工具化            100%
Phase 3 回顾与体验修正          100%
Phase 3.5 收口与恢复能力        100%
Phase 4 系统化与扩展能力         40%
```

## 最近做了什么

### 2026-06-09：把“启动后内容就绪”这件事继续做实

这次查看工作区时，我确认到一条还没提交、但已经很值得记录的新进展：项目正在把“应用启动后怎么准备本地内容”收成一条更稳定的链路。

现在新增了一个 `StartupContentSyncService`，负责在启动时先尝试加载本地数据库内容，再判断是否需要应用打包在应用里的内容同步包。如果数据库还没准备好，就先导入种子内容；如果同步失败，也会回退到 JSONL 种子源，不会让启动链路直接断掉。

这件事的重要性不在于它看起来多炫，而在于它把“内容能不能稳定可用”从单次导入，推进到了“每次启动都能自我修复和兜底”的状态。对于一个本地优先的训练应用，这类底座能力非常关键。

### 2026-06-08：本地内容同步从“预留方案”推进到“整包闭环”

6 月 8 日有一笔已经提交的新进展，是把本地内容同步真正落成了一条可运行的整包流程。

简单说，现在项目不只是“未来想做内容同步”，而是已经把同步包、版本信息、导入逻辑和失败兜底串起来了。应用可以识别本地打包的内容包版本，把内容导入数据库，并在需要时继续回退到旧库或种子源。

这一步解决的是内容演进的基础问题：以后动作库、说明文本和媒体元数据要更新，不需要每次都靠手工替换散落的数据文件，项目已经开始具备“成包更新内容”的基础能力。

### 2026-06-08：开始预埋商业化权限系统，但不破坏免费主链

同一天还有另一笔已经提交的进展，是商业化权限脚手架。

这次并没有直接接支付，也没有突然把核心训练功能做成付费墙，而是先把会员层级、商品目录、权限判断和本地 entitlement 存储这些底层结构搭起来。

它的意义在于：以后如果要做 Pro 或订阅版，不需要把现有页面逻辑再推倒重来。更重要的是，当前设计明确保留免费主链不断裂，也就是 `首页 -> 训练预览 -> 训练执行 -> 训练总结 -> 回顾` 这条基础训练闭环仍然可用。

### 2026-06-08：主训练体验继续往统一视觉语言收口

前一轮已经开始把 Home、训练预览、训练执行、训练回顾和动作详情收成同一套更稳定的视觉语言。现在从工作区状态来看，这条线还在继续推进中，说明项目已经从“先把功能拼完整”进入到“把高频体验磨顺手”的阶段。

这条线的重点不是花哨，而是让首页更聚焦、训练执行更像控制台、训练回顾更像仪表板。对于训练类工具来说，界面越清楚，用户在真正训练时越不容易分心。

## 一点代码

简洁版不会放太多代码，只保留几段最能说明设计取舍的当前仓库代码。

1RM 计算仍然使用 Epley 公式：

```arkts
export function estimateOneRepMax(weight: number, reps: number): number {
  const raw = weight * (1 + reps / 30)
  return Math.round(raw * 100) / 100
}
```

训练计划不是黑盒推荐，而是规则评分：

```arkts
if (this.containsValue(exercise.goalTags, goal.goalType)) {
  score += 40
}
if (this.hasSharedValue(exercise.equipmentIds, equipmentIds)) {
  score += 30
}
if (this.containsValue(exercise.primaryMuscleIds, muscleId)) {
  score += 20
}
```

商业化权限也先收成了集中判断，而不是散落在各个页面里：

```arkts
if (capability === 'cloud_sync' || capability === 'premium_content') {
  return 'plus'
}
return 'pro'
```

## 项目现在到哪里了

如果用一句话概括，FitTracker 现在已经不只是“能跑起来的训练记录应用”，而是在往“可维护、可演进、可发布”的产品状态靠拢。

前面的训练闭环、回顾、动作详情、本地备份和轻量回归已经基本收口；现在新推进的重点，是把内容同步、启动时兜底、未来商业化边界和发布前底座提前搭好。这样后面继续做内容更新、账号能力或付费版本时，不会把现有主线再次打散。

## 下一步

- 继续收稳启动内容同步链路，确认数据库、同步包和种子源之间的切换边界。
