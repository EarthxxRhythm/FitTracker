### 4.2 官网停站（已执行 2026-11-10）

腾讯云《首次备案》原文：「如果您的网站/域名……**从未办理过备案，在开通服务前，需在腾讯云备案系统进行首次备案的操作**。」

腾讯云整改通知已直接点名 `http://www.earthrhythm.cloud` 与 `https://www.earthrhythm.cloud` 开站。已按整改要求停站。

**做了什么**（服务器 `ubuntu@106.55.37.80`）：

| 项 | 内容 |
| --- | --- |
| 配置文件 | `/opt/fittracker/caddy/Caddyfile` |
| 备份 | `/opt/fittracker/caddy/Caddyfile.bak-20261110` |
| 改动 | 官网块 `earthrhythm.cloud, www.earthrhythm.cloud` 的 `root`/`file_server` 全段替换为 `abort`；**新增** `http://` 显式站点块同样 `abort` |
| 为什么加 http 块 | 只删 `file_server` 时，Caddy 仍为 80 端口保留自动 308 → https 重定向，`http://` 会返回响应，备案核查仍判「开站」（实测首轮 `http://` 返回 308） |
| inode | `398747` → `398747`（用 `cat >` 原地覆写，未用 `sed -i`，规避单文件 bind mount 陷阱） |
| 生效方式 | `docker restart fittracker-caddy`（不能 reload） |

**验证**（2026-11-10 16:56，本机 curl）：

| 地址 | 结果 |
| --- | --- |
| `https://earthrhythm.cloud/` | `Empty reply from server`（curl 52） |
| `https://www.earthrhythm.cloud/` | `Empty reply from server` |
| `http://earthrhythm.cloud/` | `Empty reply from server` |
| `http://www.earthrhythm.cloud/` | `Empty reply from server` |
| `https://www.earthrhythm.cloud/legal/privacy.html` | `Empty reply from server` |
| `https://api.earthrhythm.cloud/auth/v1/health` | **401**（链路正常，缺 apikey 属预期） |
| `https://api.earthrhythm.cloud/rest/v1/` | **401**（同上） |

`api` 子域不受影响：Caddy 日志确认证书管理仍覆盖三域名，库表与 APP 后端正常。

**恢复方式**（备案下号后）：

```bash
cd /opt/fittracker/caddy
cp -a Caddyfile.bak-20261110 Caddyfile   # 或手工把 abort 换回 root/file_server 块
# 同时删掉新增的 http:// 站点块
cat Caddyfile > /tmp/c && cat /tmp/c > Caddyfile   # 保持 inode（或直接 cp -a 覆盖前先确认挂载）
docker restart fittracker-caddy
```

⚠ `cp -a` 会新建 inode，容器可能仍挂旧文件。稳妥做法：`cat 备份 > Caddyfile` 原地覆写，再 `docker restart`。

**副作用**：官网与法务页对外不可访问期间，应用市场提审若要填「隐私政策链接」需改用其他可达地址（`apps/` 内零引用该域名，APP 内法务文档为本地资源，不受影响）。

### 4.6 官网能否搬去别处开站（2026-11-10 结论）

腾讯云整改通知原文末句：「**如果网站实际未接入腾讯云，请忽略。**」——理论上搬走即可。但有一条硬约束：

**APP 备案表单里填的域名是根域 `earthrhythm.cloud`**（2026-11-10 用户从备案页确认，表单回显为该值）。腾讯云文档要求备案域名与接入云资源对应，根域若解析离开腾讯云，存在被判定「接入不符」从而冲击 APP 备案 `赣ICP备2026026335号-1A` 的风险。**因此根域 A 记录不动。**

| 方案 | 做法 | 风险 | 体验 |
| --- | --- | --- | --- |
| A 只挪 www | `www` CNAME/CNAME 到境外平台，根域与 api 留腾讯云 | 低 | 根域 `earthrhythm.cloud` 仍打不开，只能走 `www` |
| B 全挪境外 | 根域 + www 一起改 | **高**——直接对抗 APP 备案的域名关联 | 官网地址正常 |
| C 官网独立托管 | 新域名或 `*.github.io` / `*.pages.dev`，**完全不碰 `earthrhythm.cloud`** | 无 | 地址不是主域，但可立即上线 |
| D 原地办备案 | 保持停站，走本文流程 | 无 | 1–3 周后恢复正常 |

**推荐 C 作为过渡**：官网放境外静态托管（GitHub Pages 已有仓库可直接用、Cloudflare Pages 大陆访问更好），`earthrhythm.cloud` 与 `api.earthrhythm.cloud` 一律不动。备案下号后按 §4.4 恢复主域官网，境外托管留作镜像或下线。

⚠ 境外托管不需要 ICP 备案，但这不等于备案义务消失——《互联网信息服务管理办法》要求境内提供互联网信息服务须备案。C 方案是「官网暂用境外地址过渡」，不是长期合规形态。

`api.earthrhythm.cloud` 任何时候都不能动：它是 APP 后端（`rawfile/supabase.json`（鸿蒙端 AppScope 资源目录下，该文件被 gitignore、不入库） 的 `"url": "https://api.earthrhythm.cloud"`）。

## 7. 与 APP 备案的关系

| | ICP 网站备案（本文） | ICP APP 备案（`beian-materials.md`） |
| --- | --- | --- |
| 指向 | 域名 + 服务器 | APP 包名 + 公钥指纹 |
| 主体材料 | 身份证、域名、服务器 | 应用名称、包名、公钥、MD5 指纹 |
| 结果 | 网站备案号，展示在网页底部 | APP 备案号，回填应用市场提审 |

两者可以同一订单提交（腾讯云支持一个订单同时备案网站与 APP，个人主体各限 1 个），互不冲突。

### 7.1 为什么 APP 备案不能替代网站备案（同一域名）

备案登记的单位是**服务项**，不是域名。同一个 `earthrhythm.cloud`，两种用法算两笔：

| | APP 服务项（已有，`-1A`） | 网站服务项（缺） |
| --- | --- | --- |
| 登记对象 | APP（包名 / 公钥 / MD5） | 网站（域名 / 网站名称 / 服务内容） |
| 覆盖的用法 | APP 通过该域名调用后端接口 | 该域名对外提供网页 |
| 对应实例 | `api.earthrhythm.cloud` | `earthrhythm.cloud`、`www.earthrhythm.cloud` |

三条互相印证的证据：

1. **腾讯云整改通知的判词**：「APP备案域名对应网站未备案且开站」——它承认域名在 APP 备案里，同时判定网站服务项缺失。若 APP 备案能覆盖网站，这条通知不成立。
2. **整改通知点名的开站地址只有 `http://www.earthrhythm.cloud` 与 `https://www.earthrhythm.cloud`**，未点 `api.earthrhythm.cloud`。而 APP 实际连的就是 api 子域（`rawfile/supabase.json`（鸿蒙端 AppScope 资源目录下，该文件被 gitignore、不入库） 的 `"url": "https://api.earthrhythm.cloud"`），说明腾讯云认这个边界：接口归 APP 备案，网页归网站备案。
3. **办一次即可覆盖全部子域**：腾讯云文档原文「二级域名 ICP 备案后对应的三级域名、四级域名可以正常使用」。`earthrhythm.cloud` 的网站备案下来后，`www` 与 `api` 都在覆盖范围内，不必逐个备案。
