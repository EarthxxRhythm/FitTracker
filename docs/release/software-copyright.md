# 菲特 软件著作权登记（软著）指南

> 建立：2026-10-11。用途：国内应用市场（含华为应用市场）提审时通常要求提供软著登记证书。本文件收录官方口径、本项目实测参数与材料准备方式。
> 配套：`docs/release/beian-materials.md`（APP 备案取证）、`docs/release/release-build-runbook.md` §12（上架材料待办）。

## 1. 结论先行

- **官方渠道免费**：软件著作权登记无登记费（国家层面已停征），自己办不花钱。
- **代办是服务费**：市面 400–1000 元（半包仅代提交 / 全包代写材料），材料责任仍在你这边；材料不合规被退，代办也救不了。
- **法定审查期 60 日**：依据《计算机软件著作权登记办法》第二十条——「中国版权保护中心应当自受理日起 60 日内审查完成」。实际多为 1–2 个月，**被退回补正要重新排队**。
- **入口**：中国版权保护中心 <https://www.ccopyright.com.cn/> → 版权登记 → 软件登记（<https://register.ccopyright.com.cn/registration.html#/registerSoft>）。
- ⚠️ **软著比备案慢**：备案 1–3 周，软著 1–2 月。若目标市场要求软著，**它是上架链上的关键路径，应最先启动**。

### 软件还没到最终版本，能申请吗？——能，而且现在就该申请

登记的门槛是**软件已开发完成并可固定为材料**，不是「已上线」或「最终版本」。当前仓库已能构建出可运行包（鸿蒙 1.1.0、安卓 0.1.0），条件已满足。

| 疑问 | 口径 |
| --- | --- |
| 还没上架 | 申请表「首次发表日期」选 **未发表** 即可，不影响登记与后续上架 |
| 后面还会改 | 登记的是**提交那一刻的版本快照**；后续继续开发不影响本次登记效力。应用市场核验的是「有没有软著」，**不比对代码** |
| 代价是什么 | 将来若需维权，保护范围以登记的版本为界（对付上架核验完全够用） |
| 版本号要与应用版本一致吗 | **不需要**。软著版本号与应用 `versionName`（鸿蒙 1.1.0 / 安卓 0.1.0）是两套编号 |
| 版本号怎么填 | 官方填表说明：建议 `V1.0` 或 `1.0`（两者均可）。**证书以申请表填报为准**；申请表、源代码页眉、说明书三处的版本号必须**完全一致**（含有无 V）——这是最常见的补正点 |
| 开发完成日期 | 填该版本形成之日（提交前近期日期即可） |

> 注：据第三方来源，自 2024-04-23 起软著证书样式已不再记载「开发完成日期」与「首次发表日期」两项，但申请表可能仍需填写——**以登记系统当期实际表单为准**（本项未取到官方原文）。

**结论**：不要因为「还不是最终版」而拖延。软著周期 1–2 个月，是上架链上最长的一段，早提交早下证。

## 2. 材料四要素

| 材料 | 要求 |
| --- | --- |
| 申请表 | 线上填写：软件全称、简称、版本号、开发完成日期、首次发表日期、著作权人 |
| **源程序** | 连续的前 30 页 + 后 30 页；**每页不少于 50 行** |
| **说明书**（文档） | 连续的前 30 页 + 后 30 页；**每页不少于 30 行**；图文并茂说明软件功能与操作流程 |
| 身份证明 | 个人：身份证；企业/个体：营业执照 |

> 官方原文（填表说明「4. 软件鉴别材料 · 一般交存」）：整个程序和文档不到 60 页的，应当提交整个源程序和文档；除特定情况外，**程序每页不少于 50 行，文档每页不少于 30 行**。

## 3. 本项目实测参数

- `apps/harmony/entry/src/main/ets`：**97 个 `.ets` 文件、28,656 行**（剔除空行与纯注释后 25,571 行）——远超 3000 行门槛。
- 因此源程序须按「前 1500 行 + 后 1500 行」截取，共 60 页（每页 50 行）。
- **提交前必须排除的内容**（出现即可能被质疑或泄露）：
  - 签名材料类：`build-profile.json5` 中的 `signingConfigs` 本机路径与口令密文；
  - 任何凭据文件：`agconnect-services.json`、`local.properties`、Supabase 的 URL/Key；
  - 第三方库源码（`oh_modules/`）—— 只提交自有代码。

## 4. 命名一致性（最容易踩的坑）

应用市场会核验软著名称与上架名称是否一致（或明显关联），不一致会被要求补交证明材料。**先定名，再提交软著**——软著改名要走变更登记，很慢。

当前名称链路：

| 位置 | 值 | 落点 |
| --- | --- | --- |
| **桌面图标下显示的名字** | `菲特` | `apps/harmony/AppScope/resources/base/element/string.json` 的 `app_name`；安卓侧 `app/src/main/res/values/strings.xml` |
| **应用市场的上架名** | `菲特` | AGC / 各市场后台填写 |
| **软著证书的软件全称** | `菲特健身训练软件`（待登记） | 中国版权保护中心登记 |
| **软著证书的软件简称** | **`菲特`** | 同上。官方填表说明：「简称：对软件全称进行简化的名称。没有简称请留空，不要填写『无』。不要与软件全称完全相同」 |
| 法务文本中的品牌名 | `菲特（FitTracker）` | `docs/legal/*.md`、`apps/harmony/entry/src/main/resources/rawfile/legal/*.txt` |

**注意**：桌面图标下面是「菲特」，**不是**「菲特健身训练软件」——后者只是软著证书上的正式登记名。桌面名要短（图标下空间有限），软著全称按惯例取「XX软件」形式。

怎么填才两边都对得上：

- 软著**全称**：`菲特健身训练软件`
- 软著**简称**：`菲特` ← **这一栏才是让桌面名 / 市场名与软著对上的关键**。官方填表说明确认简称栏存在且可选填；填上之后「应用名 = 软著简称」逐字一致，市场核验无歧义
- 若确实不填简称：全称仍是 `菲特健身训练软件`，提审时若被质疑名称不一致，按市场要求补说明（华为云商店文档中即有「商品名称与软著中的软件名称不一致」的声明函模板场景）

版本号取 `V1.0`。

- 软件环境：HarmonyOS 6.0.2(22)
- 编程语言：ArkTS（ArkUI 声明式）
- 源程序量：28,656 行（2026-10-12 实测，见 §3）

## 7. 多平台（鸿蒙 / 安卓 / iOS）下的策略

本产品同时上架鸿蒙与安卓，并计划开发 iOS 端。多平台对软著与备案的影响如下。

### 7.1 软著：登记一份即可覆盖三个市场

- 应用市场上架核验的是「有没有软著 + 名称能否对上」，**不是**「软著是否覆盖该平台的代码」。三端应用名统一为「菲特」，一个软著（全称 `菲特健身训练软件` / 简称 `菲特`）即可覆盖。
- 源程序材料交任一端的实现即可（当前取的是鸿蒙端：97 个 `.ets` / 28,656 行）。官方只要求「连续的前 30 页 + 后 30 页」，本就不要求覆盖全部代码。
- 若未来 iOS 端为**完全独立开发**、且希望单独取得保护，可以另行登记一份——但那要多走一遍 1–2 个月周期，对上架并非必需。

### 7.2 备案：按平台分别登记

- 同一主体下的多平台需在备案中分别登记（各平台包名 / Bundle ID 不同，用于备案的证书指纹材料也不同）。
- 鸿蒙侧材料见 `docs/release/beian-materials.md`（公钥 + MD5 已备齐）；安卓侧待 keystore 生成后从签名证书提取，流程见 `docs/release/android-signing-and-store.md`。
- iOS 端上线同样需要 APP 备案，材料提前准备。

### 7.3 法律文本：各端一份，不可互相复制

- 鸿蒙端隐私政策写的是「联网行为仅指向华为 AGC」（`docs/legal/`）；安卓端写的是 Supabase（`apps/android/app/src/main/assets/legal/`）。两端**描述各自的真实实现**，条款不能照搬。
- iOS 端上线时需要第三份，其云服务表述取决于 iOS 接哪套后端。

> 后端现状（`contracts/README.md` §0、§7）：两端**契约统一、供应商实现分家**——鸿蒙走华为 AGC，安卓走自托管 Supabase，云端数据互不可见，跨端迁移目前只能靠手动导出/导入备份包。iOS 端接哪套后端是独立的架构决策，会同时决定 7.3 里第三份法律文本怎么写。
