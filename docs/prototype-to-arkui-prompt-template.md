# 网页原型 → ArkUI 迁移提示词模板（通用）

> 跨项目复用的迁移提示词骨架。方括号 `[ ]` 处按项目替换；FitTracker 的具体取值见配套附录
> `docs\prototype-to-arkui-prompt-fittracker.md`。

## 这份模板解决什么

把「HTML 原型 → ArkUI 页面」交给 agent 时，最常见的失败不是写不出代码，而是**把迁移当成版式复刻**——
只对齐盒子和间距，漏掉交互状态、动效、可访问性，最后「看起来像」但用起来不对。

| 根因 | 典型表现 |
|---|---|
| 把「迁移」等同于「版式复刻」 | 只对齐盒子与间距，弹层／空态／错误态／动效全没做 |
| 规格源被文档冒充 | 读了 README 就动手，而 README 与源码实际冲突 |
| 隐藏的像素基准 | 同一批 HTML 里混了缩放画布与直绘画布，不逐屏判定就整体偏 |
| 交互状态被无视 | 只做静态落定态 |
| 动效被当成装饰 | 只写一句「用动效 token」，不写提取与映射 |
| 验收环节可造假 | 截图工具到不了目标屏，却照常给出数字 |

## 使用方法

1. 复制下面「提示词正文」整块给 agent。
2. 按「方括号填写清单」把 `[ ]` 替换为本项目的实际路径、命令、清单来源。
3. **首次迁移只放行第 0 步**（逐屏建理解表），人工审核后再放行后续步骤。
4. 屏数多时按第 7 步分片并行，主会话保留构建／截图／提交的单写者身份。

## 提示词正文（复制这段）

```text
# 任务：把 HTML 原型迁移为 HarmonyOS ArkUI 页面（完整 UI/UX 还原）

## 角色
你是 ArkUI 还原工程师。目标不是「把 HTML 画成能跑的页面」，而是把整套 UI/UX
——设计基调、色彩、字体、组件、页面层级、交互状态、动效、可访问性——逐屏 1:1 还原。
只对齐版式而漏掉交互状态与动效，视为未完成。

## 规格源地图（缺一不可）
- 结构规格：[原型 HTML 冻结目录]
- 动效规格：[动效声明表文件]
- 令牌规格：[设计令牌文档] + [代码中的令牌文件]
- 设计基调：[产品愿景 / 视觉方向文档]
- 设计系统：[色彩 / 字体 / 图表规格]
- 组件规格：[按钮 / 卡片 / 输入 / 页头 / 标签规格]
- 页面规格：[逐页规格文档目录]
- 验收口径：[视觉验收口径文档]、[UX 验收清单]
- 屏清单与 frame 索引：[原型预览壳的 ROUTES 表]

**项目文档是索引，可能与源码冲突。冲突时一律以 HTML 源码为准。**

## 第 0 步（不可跳过）：先读懂，再写第一行 ArkTS

对每一屏，先回答下面六个问题并把结论写下来：

### 1. 画布基准是什么？
读根容器尺寸；找到 frame 容器，检查它是否有 `transform: scale(var(--...))`；读 `:root` 里缩放变量的值。
- 设计画布尺寸 + `scale(比值)` → **缩放画布**：用一个该尺寸的容器包住内容并加 `.scale({ x, y, centerX: 0, centerY: 0 })`，
  外层容器 `.clip(true)`；**容器内直接使用原型原始数值**，不要手工折算。
- 无 scale → 直绘画布，原型数值直接当 vp 用。
- 逐屏判定，不要套用「某类屏都是直绘」的假设。

### 2. 哪些区域固定、哪些滚动？
搜 `overflow-y: auto` / `overflow-x: auto` 容器。frame 外框的 `overflow: hidden` 是裁剪、不代表不可滚。
- 在滚动容器内 → 必须放进 `Scroll`；在外 → 必须留在 `Scroll` 外。
- **页头／标题／切换器可能就在滚动区内**，不要想当然把页头固定住。
- 整屏无滚动容器 → 整屏固定，不得添加 `Scroll`。

### 3. 有哪些动效？
提取：`rg -n "@keyframes|transition:|animation:|:active|cubic-bezier" <原型目录>/*.html`，
与动效声明表核对，整理「元素 → 属性 → 时长/缓动/关键帧% → 触发条件」。
分三类：`:active` 按压反馈、单段 `transition`、`@keyframes` 关键帧序列（含循环脉冲）。

### 4. 有哪些交互状态？
逐屏找：弹层（`sheet` / `modal` / `drawer` / `backdrop`）、反馈（`toast` / 字段错误）、
空态（`empty`）、占位态（`placeholder`）、禁用态、加载态、校验错误态。
把每个状态的**触发条件、视觉、文案、退出路径**都记下来。这些不是可选项。

### 5. 页面信息层级是什么？
读对应的页面规格文档，写出本屏的 Level 1（主导区域）/ Level 2（上下文）/ Level 3（次级入口），
以及**唯一的主 CTA** 是哪个。目标：用户 2 秒内知道「现在该做什么」。

### 6. 结构与精确值
DOM 树 → ArkUI 组件树的映射；尺寸、颜色、字号、行高、间距、文案逐字抄（文案含标点，UTF-8 读文件）。

## 第 1 步：视觉系统

- **色彩**：从 `:root` 与色彩规格取。`rgba(r,g,b,a)` → `#AARRGGBB`，`AA = round(a*255)`
  （例 `rgba(255,255,255,.56)` → `#8FF3FBF7`）。
  遵守项目对**强调色使用范围**的硬规则（通常：只用于主操作、激活态、完成态、关键数据；
  不得用于整页背景、所有卡片、正文、装饰噪声）。
- **字体**：按字体规格的层级模型选择 token。**关键数字层级要强于邻近标签**；避免同屏过多字重跳变。
- **间距／圆角／阴影**：优先用项目 token，不散落魔法值。
- **图标**：优先复用现有资源；缺失时用 ArkUI 图元内联。图标只用于提升扫读，不给每个按钮加图标。

## 第 2 步：组件与页面落地

### 组件
- **按钮**：按项目定义的层级（主 / 次 / 幽灵）。每屏**只能有一个最响的主 CTA**。
- **输入**：base / focus / completed / error 四态都要做；错误用**局部字段强调 + 简短文案**，不整段变红。
- **页头**：遵守**高度纪律**——不得挤占首屏把主操作推下去。
- **卡片**：分层而非堆叠，主卡可用更强 surface，次级卡保持安静。

### 页面层级
- 写出 Level 1/2/3，确保主导区域在首屏、唯一主 CTA 明显、次级入口不与之竞争。
- 自检：**用户 2 秒内能否知道该按什么**。若需读多块同权重文本才能理解，层级失败。

### 布局与自适应
- `Column/Row/Scroll/Flex` + `.layoutWeight()` 或百分比宽，对应 HTML flex 语义。
  **`Scroll` 内部的 `.layoutWeight()` 不生效**，需固定尺寸处改用 `constraintSize` 或显式高度。
- `.position({x, y})` 只用于装饰性覆盖层，不用来堆整页内容。
- 左右 gutter 用项目间距 token；横向不可换行的行（chip／日期行）用横向 `Scroll`。
- 文本默认 `maxLines` + `TextOverflow.Ellipsis`；遵守 safe-area。
- **语言严格模式禁令**：按项目约束列出被禁语法（如 `any`、`@ts-ignore`、解构、嵌套函数、
  对象索引访问等），触犯即编译失败。
- **保留既有非视觉逻辑**：导航、服务调用、状态绑定不动，只改视觉层。
- **新页面三件套**：文件存在 + 注册到页面清单 + 路由常量存在。

## 第 3 步：交互状态与弹层

每个可交互元素至少实现：默认 / 按压 / 聚焦（输入类）/ 禁用。
每个数据区域至少实现：正常 / 空 / 加载 / 错误（有则做）。

**弹层**：
- 结构：`backdrop` + 内容面板；面板带对话框语义。
- 进出场：按动效声明表映射到 `animateTo` 或 `keyframeAnimateTo`。
- **必须有明确退出路径**：backdrop 点击、关闭按钮、物理返回键三者至少前两者可用。
- 弹层打开时不得让背景可交互。

**反馈**：
- `toast` 文案与原型**逐字一致**；出现后自动消失且**不阻塞**主流程。
- 表单错误就地显示在字段下方，文案逐字取自原型。

**空态**：图标 + 标题 + 提示三段，不用纯文字占位。

## 第 4 步：动效（不要当成装饰）

| 原型 CSS | ArkUI 实现 |
|---|---|
| `cubic-bezier(a,b,c,d)` | `curves.cubicBezierCurve(a,b,c,d)` |
| 时长 / delay（ms） | 原值直填 |
| `:active { transform: scale(.985) }` | `@State pressed` + `onTouch(Down/Up/Cancel)` + `.scale(...)` + `.animation({ duration, curve })` |
| `transform: translateX/Y`、`opacity` | `.translate({ x, y })` / `.opacity(...)` |
| 单段 `transition` | `animateTo({ duration, curve, delay }, ...)` |
| 多关键帧 `@keyframes` | `keyframeAnimateTo({ delay }, [{ duration, curve, event }, ...])` |
| 背景 / 边框 / 颜色过渡 | `.animation({ duration, curve: Curve.EaseInOut })` |

- 所有时长、缓动、按压缩放系数**引用项目动效 token**，不写魔法值。
- **每个可交互元素用独立状态变量**承载按压态，避免多按钮联动。
- **循环脉冲**只核动效声明表的映射关系，不逐帧截图。
- 缩放画布内的动效值由第 0 步的缩放容器承载，不单独折算。

## 第 5 步：可访问性

- **触控目标**：可点击元素最小尺寸不低于项目定义的最小触控目标。
- **语义标签**：原型里的 `aria-label` / `role` / `aria-live` 要映射到 ArkUI 无障碍属性，
  不要因为视觉一致就丢掉。
- **对比度**：正文与背景不低于 WCAG AA；原型既有的文字透明度层级不要擅自改动。
- **文字截断**：默认 `maxLines` + 省略号，避免小屏硬断行。

## 第 6 步：三轨验收

### 6.1 结构像素（最易造假）
1. 渲染参照帧（用项目的原型渲染工具，指定 frame 序号）。
2. **真实导航到目标屏**——不能只冷启动就截图：
   - 先 dump 无障碍树看冷启动落在哪屏（读屏上文本，不靠猜）。
   - 用点击注入逐跳到达，坐标取自 dump 的 bounds。
   - **每跳后重新 dump，用屏上文本确认真的到达**；到不了的如实标「无法到达」，不拿别的屏充数。
3. 对比（用项目的像素对比工具，指定裁剪区间与文本掩码）。
   - 文本掩码由无障碍树生成：bounds ÷ 设备密度 → 减去裁剪起点 → 落入裁剪区间的才计入。
   - 达标线：**非文本内容区超阈像素占比 ≤ 项目阈值**。
4. **数字自检**：若改动前后数字**逐位相同**，先怀疑「测错了屏」，回去核对导航，而不是判定改动无效。

### 6.2 动效态
1. 原型侧：用项目的原型动效帧工具（把动画暂停到中段、强制按压态）。
2. 设备侧：用项目的设备动效帧工具（点击注入 + 延迟截图）。
3. 对比：用项目的动效对比工具 → 每页每状态 MAE + 并排图 + 热力图。
4. 收敛：只改时长／缓动／关键帧百分比／缩放系数，**不动布局尺寸、颜色、文案**。
5. **如实标注已知限制**：短时按压与转场在无录屏能力的模拟器上无法逐帧静态捕获；
   减少动效偏好无直接等价；hover 态触屏无意义不实现。

### 6.3 UX 四维 checklist
逐屏逐条给出 pass/fail，任一 blocking 即不通过：

- **A 视觉一致性**：首屏层级清晰；标题/标签/辅助文本尺度关系一致；组件与间距跨屏一致；
  无旧视觉语言混入；关键动作优先级一致。
- **B 流程清晰度**：主操作 3 秒内可见；返回/下一步无需探索即可理解；支持先扫读再细读；
  次级动作分组合理；不强制绕路。
- **C 交互打磨**：无重叠/裁切/换行断裂；无空白或死链 CTA；点击常用控件无布局抖动；
  loading/empty/success/warning 状态读起来是有意为之；重复控件跨屏一致。
- **D 产品调性**：读起来是聚焦的工具而非营销页；视觉平静、密度足够、可控；
  变现入口保持次级；高级能力是整合而非粘贴。

## 第 7 步：分片并行（屏数多时）

- 分片依据：屏清单表（每个 route 一个屏文件 + frame，天然正交）。
- 每片 owner_files = 该屏页面文件 + 内容组件，**互不重叠**。
- 共享层（设计 token、路由常量、应用壳、公共组件）**先冻结**。
- 单写者纪律：构建、装包、设备截图、版本提交**只由主会话执行**。
- **不要相信子代理报告的完成状态**：每批结束后核对实际改动文件，再逐个读文件核验内容。

## 交付格式

每屏一行：改了哪些文件 + 参照帧/设备帧/动效帧/报告路径 + **像素超阈% + 动效态 MAE + A/B/C/D 四维结论**
+ 未验证项。未验证的必须显式写「未验证」并说明原因。

## 负面清单（明确不要做）

- 不要用原型 HTML 之外的文档当规格。
- 不要把「迁移」做成「版式复刻」——交互状态与动效是同一轮交付物。
- 不要给「内容不溢出」的屏加 `Scroll`；也不要把所有页头都固定住。
- 不要为了「更好看」提高文字对比度或加深强调色饱和度。
- 不要让次级卡片与主 CTA 竞争视觉权重。
- 不要在动效／UX checklist 未做时只报像素数字。
- 不要把「命令跑过」当「验证通过」——要有退出码、数字、报告路径。
- 不要手工折算缩放画布数值——用缩放容器，内部保持原始值。
```

## 方括号填写清单

替换提示词正文里的每个 `[ ]` 前，先确认本项目的这八项都有确定落点：

| 需要填写 | 说明 |
|---|---|
| `[原型 HTML 冻结目录]` | 只读的设计基线目录，通常是上游设计稿的整体快照 |
| `[动效声明表文件]` | 逐屏 `transition` / `:active` / `@keyframes` 的汇总表；没有就从 HTML 抽取生成 |
| `[设计令牌文档]` + `[代码中的令牌文件]` | 前者是规格汇总，后者是代码里真正被引用的 token 定义 |
| `[产品愿景 / 视觉方向文档]` | 决定「工具感还是营销感」的判据来源 |
| `[色彩 / 字体 / 图表规格]` | 强调色的使用范围硬规则通常写在这里 |
| `[按钮 / 卡片 / 输入 / 页头 / 标签规格]` | 组件级规则，含各交互状态 |
| `[逐页规格文档目录]` | 信息层级 Level 1–3 与主 CTA 的定义处 |
| `[视觉验收口径文档]` + `[UX 验收清单]` + `[原型预览壳的 ROUTES 表]` | 分别提供阈值口径、四维 checklist、屏清单与分片依据 |

**若某项在本项目不存在**：不要删掉提示词里的对应步骤，而是在附录里注明「本项目暂无，按 HTML 源码推断」，
免得 agent 因为找不到规格而跳过该维度。

## 为什么这样写

| 提示词片段 | 依据 |
|---|---|
| 「规格源地图」列全八类 | 只引结构 + 动效两类，必然漏掉设计系统／组件／页面规格 |
| 第 0 步的「六问」 | 漏掉「交互状态」与「页面信息层级」是版式复刻式迁移的主要缺陷 |
| 强调色硬规则原样写入 | 色彩规格通常含明确禁令，不写 agent 会滥用强调色 |
| 「唯一主 CTA」 | 按钮规格与页面规格都把动作优先级列为首要判据 |
| 「页头高度纪律」 | 页头是首屏空间的主要消耗者 |
| 输入四态 | 输入规格单列了 focus / completed / error |
| 「弹层三条退出路径至少两条」 | 原型弹层通常同时有 backdrop／关闭按钮／Esc |
| 空态三段式 | 原型空态就是「图标 + 标题 + 提示」结构 |
| 动效映射表 + 独立状态变量 | 动效有确定的映射关系，逐元素独立状态避免联动 |
| 三轨验收中的「数字逐位相同 → 先怀疑测错屏」 | 这是最容易把「测错」误判成「改动无效」的场景 |
| 「不要相信子代理完成状态」 | 平台消息通道不可靠时，返回状态与文件实况可能不一致 |

## 与项目附录的分工

- **本模板**：不含任何具体项目路径，可直接移植。
- **项目附录**：填入本项目八项规格源的实际路径、屏清单表、可执行命令、已踩过的坑。
  参见 `docs\prototype-to-arkui-prompt-fittracker.md`。
