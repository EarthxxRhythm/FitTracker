# 旧页面治理清单

目的：统一主线路由，避免旧页面继续混入 `main_pages.json`。

## 现阶段主线

以下页面保留在当前主流程内：

- `app/StartupPage`
- `pages/LoginPage`
- `pages/RegisterPage`
- `features/onboarding/pages/GoalSetupPage`
- `pages/HomePage`
- `features/exercise/pages/ExerciseDetailPage`
- `features/workout/pages/WorkoutPreviewPage`
- `features/workout/pages/ActiveWorkoutPage`
- `features/workout/pages/WorkoutSummaryPage`
- `features/review/pages/ReviewHomePage`

## 历史页面

以下页面暂不进入主注册链路，保留为历史功能或后续迁移素材：

- `pages/Index.ets`
- `pages/PlanDetailPage.ets`
- `pages/ExerciseLibraryPage.ets`
- `pages/ProfilePage.ets`

## 后续迁移建议

- `pages/Index.ets`：作为旧首页保留，后续可删除或转成跳转壳。
- `pages/PlanDetailPage.ets`：后续若需要单独计划详情页，再迁到 `features/workout/pages/`。
- `pages/ExerciseLibraryPage.ets`：后续迁到 `features/exercise/pages/`，作为动作库入口。
- `pages/ProfilePage.ets`：后续迁到 `features/account/pages/`，当前不进入主链路。
- `pages/StatsPage.ets`：后续迁到 `features/review/pages/` 或单独分析模块。
- `pages/WorkoutRecorderPage.ets`：与新版 `ActiveWorkoutPage` 功能重叠，优先退出主链路。
- `pages/RudderStyleTab.ets`：无明确业务归属，建议退出注册链路。

## 路由原则

- `main_pages.json` 只保留主线和必要入口。
- 新增页面前先确认归属，再决定是否注册。
- 旧页面若不再使用，先移出注册链路，再决定是否删除。
