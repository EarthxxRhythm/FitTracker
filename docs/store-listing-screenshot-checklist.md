# FitTracker 应用市场截图清单（Release 包实拍）

本清单规定：从**正式 release 签名包**安装到目标真机后，按上架规格实拍市场截图的内容、顺序与命名，供上架材料提交使用。

> 执行边界：构建、签名、安装 HAP 与设备实拍均由协调者执行；本文档只定义"拍什么、拍到什么状态、如何命名"。

## 一、规格口径（提交前须在后台核对）

应用市场对截图的尺寸、张数与体积要求可能调整，**最终以 AppGallery Connect 提交页面的实时提示为准**。提交前请逐项核对后台提示，以下为常见参考口径：

- 方向：竖屏（手机应用）；
- 比例：9:16；
- 分辨率：不低于 1080×1920 像素，建议 2160×3840；
- 格式：PNG 或 JPG；
- 张数：至少 3 张，建议 5～8 张；
- 单张体积：通常不超过 5 MB；
- 首图（第 1 张）为列表页展示图，信息密度最高、最能说明产品价值。

> 若后台提示与本参考不一致，以后台为准，并回填到本清单。

## 二、拍摄前置条件

1. 安装**已签名 release 包**（非 debug 包），确认无调试水印、无性能浮层、无英文 `Day N` 等占位文案；
2. 使用真机（建议目标机型，非模拟器），系统语言设为**简体中文**；
3. 准备可展示的本地数据：至少 1 个进行中的训练计划、若干历史训练记录、若干身体数据，避免空白态上镜；
4. 状态栏建议统一（时间、电量、信号），或按市场要求裁掉状态栏；
5. 逐张截图后立即核对：文本无截断、无遮挡、无溢出。

## 四、素材规范

1. **语言**：全部为简体中文界面；
2. **数据**：使用真实感数据，不得出现 `0`、空列表、`test`、`demo` 等未完成态（本项目已有 `demo_data` 演示种子，可由协调者在安装后注入）；
3. **隐私**：截图中不得出现真实个人信息、真实手机号或邮箱；
4. **一致性**：所有截图使用同一机型、同一主题、同一状态栏样式；
5. **叠加文案**：如需在图上叠加卖点文字，文字须位于安全区内，不遮挡关键 UI，且不与系统语言冲突。

## 五、产出与存放

- 建议存放于 `docs/legal/` 之外的发布素材目录（如 `docs/release-assets/screenshots-<versionName>/`），**不**加入主分支的源码目录；
- 文件命名遵循上表 `NN-<name>.png` 规则，便于与后台提交顺序一一对应；
- 提交后在本清单回填实际分辨率与张数，作为交付记录。

## 六、验收口径

- [ ] 截图张数满足后台最低要求；
- [ ] 每张分辨率、比例、体积符合后台提示；
- [ ] 8 张主图与上表页面、状态一一对应；
- [ ] 无空白态、无占位文案、无调试信息；
- [ ] 首图能独立说明产品核心价值；
- [ ] 已从 release 签名包实拍（非 debug 包）。
