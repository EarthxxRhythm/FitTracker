# FitTracker 设计系统与代码规范

**版本：** MVP 收口版  
**日期：** 2026-05-23  
**适用范围：** HarmonyOS ArkUI / ArkTS 严格模式 / FitTracker 主项目

## 1. 工程边界

FitTracker 当前以目标驱动训练闭环为主线。新增代码必须服务以下链路之一：

1. 目标设置。
2. 今日训练首页。
3. 训练预览。
4. 训练执行。
5. 训练复盘。
6. 训练回顾。
7. 动作详情与本地动作库能力。

非 MVP 页面不得注册到 `main_pages.json`，也不得新增到 `AppRoutes.ets`。

## 2. 目录职责

| 目录 | 职责 |
| --- | --- |
| `entry/src/main/ets/app/` | 启动页、路由常量、全局 store 名称、启动判断 |
| `entry/src/main/ets/pages/` | 当前保留首页 `HomePage`，旧页面不作为 MVP 入口 |
| `entry/src/main/ets/features/onboarding/` | 目标设置 |
| `entry/src/main/ets/features/workout/` | 训练预览、执行、复盘 |
| `entry/src/main/ets/features/review/` | 训练回顾 |
| `entry/src/main/ets/features/exercise/` | 动作详情和后续动作库页面 |
| `entry/src/main/ets/shared/models/` | 跨功能业务模型 |
| `entry/src/main/ets/shared/services/` | 目标、计划、训练记录等业务服务 |
| `entry/src/main/ets/common/styles/` | Design Tokens |

## 3. ArkTS 严格模式规则

所有 `.ets` 文件必须遵守：

- 不使用 `any`、`unknown`、`as any`、`as const`。
- 不使用对象解构、数组解构、`for..in`、`in` 运算符。
- 不使用动态索引访问，例如 `obj["field"]`。
- 对象字面量必须对应明确的 `interface` 或 `class`。
- 数组必须具备明确元素类型，例如 `const items: Exercise[] = []`。
- import 必须位于文件顶部，注释可作为文件头保留。
- 不使用嵌套函数声明；需要局部行为时使用箭头函数属性或拆成方法。
- 不使用 `require`、`globalThis`、命名空间模拟对象。

推荐模式：

```ts
interface GoalOption {
  id: string
  title: string
}

function createGoalOption(id: string, title: string): GoalOption {
  const option: GoalOption = {
    id: id,
    title: title
  }
  return option
}
```

## 4. 页面结构规范

页面组件使用固定形态：

```ts
@Entry
@Component
export struct XxxPage {
  @State loading: boolean = true

  async aboutToAppear(): Promise<void> {
    this.loading = true
    try {
      // load state
    } catch (e) {
      // keep a recoverable state
    }
    this.loading = false
  }

  build() {
    Scroll() {
      Column({ space: SpacingTokens.LG }) {
        // content
      }
    }
    .width('100%')
    .height('100%')
    .backgroundColor(ColorTokens.BG_PRIMARY)
  }
}
```

要求：

- 每个注册页面必须有且只有一个 `@Entry`。
- 页面状态用 `@State` 承载，不把业务状态藏在 UI 片段中。
- 页面只负责展示、交互和调用服务；不在页面内硬编码复杂业务规则。
- 路由跳转必须使用 `AppRoutes` 常量。
- `router.getParams()` 必须放在 `try-catch` 中，并使用显式类型。

## 5. 路由规范

MVP 仅允许以下路由常量：

| 常量 | 路由 |
| --- | --- |
| `STARTUP` | `app/StartupPage` |
| `GOAL_SETUP` | `features/onboarding/pages/GoalSetupPage` |
| `HOME` | `pages/HomePage` |
| `WORKOUT_PREVIEW` | `features/workout/pages/WorkoutPreviewPage` |
| `ACTIVE_WORKOUT` | `features/workout/pages/ActiveWorkoutPage` |
| `WORKOUT_SUMMARY` | `features/workout/pages/WorkoutSummaryPage` |
| `REVIEW_HOME` | `features/review/pages/ReviewHomePage` |
| `EXERCISE_DETAIL` | `features/exercise/pages/ExerciseDetailPage` |

新增页面必须先说明它在训练闭环中的位置，再加入 `AppRoutes.ets` 和 `main_pages.json`。

## 6. 服务层规范

服务层遵循单例导出：

```ts
class GoalRepositoryImpl {
  async loadGoal(context: Context): Promise<UserGoal | undefined> {
    // implementation
  }
}

export default new GoalRepositoryImpl()
```

要求：

- 调用方不得 `new` 服务类。
- preferences store 名称集中在 `FitTrackerStores`。
- 服务方法接收 `context: Context`，页面用 `getContext(this)` 传入。
- 服务层返回业务模型，不返回 UI 文案。
- 计划生成逻辑集中在 `PlanEngine`，首页只调用 `generatePlan(goal)`。

## 7. Design Tokens 规范

所有视觉值优先来自 `DesignTokens.ets`：

| 类型 | Token |
| --- | --- |
| 颜色 | `ColorTokens.*` |
| 字号 | `FontTokens.*` |
| 间距 | `SpacingTokens.*` |
| 圆角 | `RadiusTokens.*` |
| 触控尺寸 | `TouchTokens.*` |

禁止：

- 在页面内硬编码品牌色、背景色、正文色。
- 为同类按钮随意增加阴影或圆角。
- 在按钮、卡片、列表中使用不一致的 padding。

允许：

- 百分比宽高如 `'100%'`。
- 业务相关数字，如训练天数、动作组数、分钟数。
- ArkUI 必需的少量固定尺寸，但应优先沉淀到 token。

## 8. 文案规范

- 所有用户可见文案使用简体中文。
- 页面标题使用名词短语：`今日训练`、`训练预览`、`训练执行`、`训练复盘`、`训练回顾`。
- 按钮文案使用动作短语：`开始今日训练`、`查看训练回顾`、`调整训练目标`。
- 不使用开发占位文案，如 `placeholder`、`TODO`、`Coming soon`。

## 9. 动作与视频内容规范

- 不接入 MuscleWiki 官方 API。
- 不内置未授权视频、图片或动作数据。
- 动作数据进入自建库后，通过内容服务或本地数据库读取。
- 页面不得直接写死大批动作内容；临时 MVP 数据应集中在计划或内容服务中。
