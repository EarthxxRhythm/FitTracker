# FitTracker 设计系统与代码规范

版本：V2.0 重构版
日期：2026-05-23
适用范围：HarmonyOS ArkUI / ArkTS 严格模式 / 目标训练闭环架构

## 1. 总原则

- 新项目采用 feature-first 架构。
- 页面服务于训练闭环：目标配置、计划生成、训练执行、训练复盘、下次调整。
- 不接入 MuscleWiki 官方 API。
- 动作、视频、计划模板和替代动作来自 FitTracker 自建内容库。
- 首包内置核心 seed 数据，后续支持自建后台内容更新。
- 用户训练记录本地优先保存，内容更新不得破坏用户数据。

规则：

- 页面命名使用 `XxxPage.ets`。
- 组件命名使用 `XxxCard.ets`、`XxxPanel.ets`、`XxxSelector.ets`。
- 服务命名使用 `XxxService.ets` 或 `XxxRepository.ets`。

## 3. ArkTS 严格模式规范

### 3.1 禁止项

- 禁止 `any`。
- 禁止 `unknown`。
- 禁止 `as any`。
- 禁止 `as const`。
- 禁止未类型化对象字面量。
- 禁止中文、连字符或动态字符串作为对象属性名。
- 禁止 `obj["field"]` 索引访问。
- 禁止 `for..in`。
- 禁止解构赋值。
- 禁止在构造函数中临时声明字段。
- 禁止 `Function.apply`、`Function.call`、`Function.bind`。

### 3.2 数据创建规范

seed/mock 数据必须通过显式 interface/class 和工厂函数创建。

```typescript
export interface MuscleGroup {
  id: string
  nameZh: string
  region: string
}

export function createMuscleGroup(id: string, nameZh: string, region: string): MuscleGroup {
  const item: MuscleGroup = {
    id: id,
    nameZh: nameZh,
    region: region
  }
  return item
}
```

### 3.3 数组规范

- 所有非空数组必须声明明确类型。
- 空数组必须有类型标注。

```typescript
const exercises: ExerciseContent[] = []
```

### 3.4 路由参数规范

- 读取路由参数必须放在 `try-catch` 中。
- 参数类型必须通过显式接口承载。
- 不允许使用 `as any` 兜底。

## 4. 数据边界规范

### 4.1 内容数据

内容数据包括：

- 肌群。
- 器械。
- 动作。
- 视频。
- 动作步骤。
- 常见错误。
- 安全提示。
- 替代动作关系。
- 计划规则。

内容数据可以由 seed 初始化，也可以由未来自建后台更新。

### 4.2 用户数据

用户数据包括：

- 目标配置。
- 生成的训练计划。
- 训练记录。
- 组数记录。
- PR。
- 疲劳反馈。
- 收藏动作。
- 内容同步状态。

用户数据必须本地优先保存。内容更新不得删除、覆盖或重写用户训练记录。

### 4.3 ID 规范

- 内容 ID 使用稳定字符串，例如 `ex_barbell_bench_press`。
- 用户数据 ID 使用本地生成 ID。
- 内容 ID 不依赖中文名称。
- 训练记录引用内容 ID，同时保存必要快照字段，避免内容改名影响历史记录。

## 5. 服务规范

### 5.1 ContentRepository

职责：

- 读取本地 seed 内容。
- 读取已同步内容。
- 按肌群、器械、难度、目标筛选动作。
- 查询动作详情。
- 查询替代动作。
- 提供内容版本信息。

不得：

- 写入训练记录。
- 生成用户计划。
- 处理 UI 状态。

### 5.2 PlanEngine

职责：

- 根据目标配置生成训练计划。
- 根据限制部位排除或降权动作。
- 根据器械选择动作。
- 生成训练日、动作、组次和替代动作。

不得：

- 直接访问页面状态。
- 直接写入持久化存储。

### 5.3 WorkoutRepository

职责：

- 保存训练草稿。
- 保存训练记录。
- 保存组数记录。
- 保存动作替换事件。
- 查询历史训练。

要求：

- 训练中输入必须本地保存。
- 保存失败必须给出可恢复状态。

### 5.4 ReviewService

职责：

- 计算完成率。
- 计算训练容量。
- 计算估算 1RM。
- 识别个人记录。
- 计算肌群覆盖。
- 生成下次训练建议。

### 5.5 SyncService

职责：

- 检查自建后台内容版本。
- 下载内容增量。
- 校验内容 schema。
- 写入内容缓存。
- 失败时回退本地内容。

不得：

- 阻塞训练记录。
- 覆盖用户数据。

## 6. UI 设计规范

### 6.1 Design Tokens

所有视觉值必须来自 token：

- 颜色：`ColorTokens`。
- 字号：`FontTokens`。
- 间距：`SpacingTokens`。
- 圆角：`RadiusTokens`。
- 阴影：`ShadowTokens`。
- 动效：`MotionTokens`。
- 触控：`TouchTokens`。

禁止在组件中硬编码颜色、字号、间距和圆角。

### 6.2 颜色语义

| 用途 | 建议 |
| --- | --- |
| 主操作 | 品牌主色 |
| 训练完成 | 成功色 |
| PR | 金色 |
| 警告和高风险动作 | 警告色 |
| 错误 | 错误色 |
| 肌群标签 | 专属肌群色 |

状态不能只靠颜色表达，必须配合文字或图标。

### 6.3 字体层级

| 场景 | Token |
| --- | --- |
| 页面标题 | `HEADLINE` |
| 卡片标题 | `TITLE` |
| 正文 | `BODY` |
| 辅助信息 | `CAPTION` |
| 标签 | `SMALL` |
| 训练计时器 | `TIMER` |

### 6.4 组件规范

基础组件：

- `AppButton`
- `AppCard`
- `AppInput`
- `SearchBar`
- `Chip`
- `SegmentedControl`
- `StatBadge`
- `PageHeader`
- `MainTabBar`

业务组件：

- `GoalQuestionCard`

- `MuscleMap`
- `ExerciseVideoPanel`
- `ExerciseInstructionTabs`
- `ExerciseReplacementSheet`
- `WorkoutSetTable`

### 6.5 训练中页面规范

- 顶部固定训练计时器。
- 当前动作信息保持可见。
- 视频区域可折叠。
- 组数记录输入必须足够大，适合训练场景单手操作。
- 结束训练必须二次确认。
- 替换动作必须记录替换原因。

## 7. 中文文案规范

- 所有用户可见文案使用中文。
- 文案集中管理在资源或常量中。
- 禁止在服务层散落 UI 文案。
- 错误提示要说明用户下一步可以做什么。

示例：

- 网络失败：`内容更新失败，已继续使用本地动作库。`
- 训练保存成功：`训练已保存。`
- 放弃训练确认：`当前训练尚未保存，确定放弃吗？`

## 8. 内容库规范

### 8.1 动作字段

```text
exerciseId
nameZh
nameEn
aliases
primaryMuscleIds
secondaryMuscleIds
equipmentIds
difficulty
goalTags
videoUrl
coverUrl
steps
cues
commonMistakes
safetyNotes
alternativeExerciseIds
contentVersion
```

### 8.2 替代动作规则

替代动作应优先满足：

1. 主要肌群一致。
2. 器械可用。
3. 难度不高于原动作。
4. 不触发用户受限部位。
5. 训练目标匹配。

### 8.3 视频规范

- MVP 可使用占位地址或本地占位图。
- 视频组件必须支持加载、失败、重试、无网络状态。
- 视频失败不影响动作步骤展示。

## 9. 持久化规范

MVP 可继续使用本地 Preferences 或项目可用的本地存储能力。

Store 建议：

| Store | 内容 |
| --- | --- |
| `fit_tracker_goal` | 当前目标配置 |
| `fit_tracker_content` | 内容版本和同步状态 |
| `fit_tracker_plans` | 生成计划 |
| `fit_tracker_workouts` | 训练记录 |
| `fit_tracker_records` | 个人记录 |

写入规则：

- 用户数据写入后必须 flush。
- 训练中草稿应定期保存。
- schema 变更必须提供迁移函数。

## 10. 初始化规范

重新初始化项目时，第一阶段只做骨架级初始化：

1. 创建 feature-first 目录。
2. 创建共享模型。
3. 创建 seed 数据。
4. 创建 repository/service 接口和空实现。
5. 创建五个 Tab 占位页。
6. 创建目标问卷占位页。
7. 更新路由配置。
8. 保留旧代码作为参考，不在第一阶段删除可用实现。

完成骨架后，再按模块迁移或重写功能。

## 11. 测试规范

优先覆盖：

- `PlanEngine` 规则生成。
- 受限部位过滤。
- 动作替换规则。
- Epley 1RM 计算。
- 训练容量计算。
- PR 识别。
- 内容同步失败回退。

测试数据必须使用显式类型和工厂函数。

## 12. 禁止事项

- 禁止接入 MuscleWiki 官方 API。
- 禁止直接复制第三方动作/视频内容到项目。
- 禁止在 UI 中硬编码视觉值。
- 禁止训练记录依赖网络成功。
- 禁止内容更新覆盖用户记录。
- 禁止在 `entry/src/main/ets/` 下创建 `node_modules`。
- 禁止新增 `any`、`unknown`、`as any`。
