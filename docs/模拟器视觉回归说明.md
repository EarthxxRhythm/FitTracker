# FitTracker 模拟器视觉回归说明

本文记录 DevEco Studio 模拟器 + HDC + Midscene 的固定回归流程。当前链路只验证 FitTracker 本地能力，不接 MuscleWiki 官方 API。

## 已验证覆盖

固定训练闭环：

```text
启动 -> 目标设置 -> 首页 -> 训练预览 -> 训练执行 -> 复盘 -> 回顾 -> 调整目标
```

认证链路回归：

```text
注册 -> 登录 -> 关闭重开 -> 会话恢复 -> 首页/目标页分流
```

高频入口 focused smoke：

```text
首页 -> 当前启用预置计划 -> 训练预览 -> 训练执行
首页 -> 训练回顾 -> 数据备份卡
首页/训练预览 -> 动作详情 -> 媒体卡
```

## 运行前准备

1. 启动并解锁 DevEco Studio 模拟器。
2. 确认 HDC 可用。

```powershell
hdc version
hdc list targets
```

3. 加载 Midscene 环境变量。

推荐直接执行本地脚本：

```powershell
powershell -ExecutionPolicy Bypass -File tools/midscene-env.ps1
```

当前经过回归验证的模型配置为：

```powershell
MIDSCENE_MODEL_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
MIDSCENE_MODEL_NAME=doubao-seed-2-0-lite-260215
MIDSCENE_MODEL_FAMILY=doubao-seed
MIDSCENE_REPLANNING_CYCLE_LIMIT=60
```

说明：
- 以前那些不可访问或只支持 text 的 `ep-*` 接入点，不适合这条视觉回归链路。
- `MIDSCENE_MODEL_API_KEY` 仍需你自己在本地环境里准备好。

4. 确认 DevEco 环境与默认 HAP 已构建。

```powershell
powershell -ExecutionPolicy Bypass -File tools/deveco-env.ps1
& 'C:\Program Files\Huawei\DevEco Studio\tools\hvigor\bin\hvigorw.bat' assembleHap --mode module -p module=entry@default -p product=default --no-parallel
```

## Focused smoke 脚本

用于只盯住高频 UI 入口，不重复跑完整训练闭环：

```powershell
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target current-plan
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target backup-card
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target media-card
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target both -CheckOnly
```

更适合真实执行的命令：

```powershell
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target current-plan -ResetAppData -RunTag real-current-plan
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target backup-card -ResetAppData -RunTag real-backup
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target media-card -ResetAppData -SkipInstall -RunTag real-media
```

说明：
- `-ResetAppData` 会在真实执行前清理应用数据，让首页/目标设置/训练预览分流更可预期。
- `-SkipInstall` 适合已经装好最新 HAP、只想快速复跑入口时使用。
- `-CheckOnly` 仍然只检查 HDC 与 HAP 前置条件，不要求设备真的跑完视觉链路。

常用参数：

```powershell
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target current-plan -CheckOnly
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target backup-card -CheckOnly
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target media-card -RunTag local-a1
powershell -ExecutionPolicy Bypass -File tools/midscene-entrypoints-smoke.ps1 -Target both -RunRoot '.\midscene_run\focused\shared-demo'
```

## 当前脚本行为

`tools/midscene-regression.ps1` 目前按以下顺序执行：

1. 检查 HDC 设备。
2. 安装或复用 HAP。
3. 启动 FitTracker。
4. 确认启动页或预期入口页可见。
5. 定位训练预览页的 `开始训练` 按钮。
6. 进入 `训练执行`。
7. 录入哑铃卧推第 1 组 `重量kg=60`、`次数=10`。
8. 保存到 `训练复盘`。
9. 进入 `训练回顾`。
10. 点击 `调整下次计划` 返回 `训练目标`。
11. 重启后确认仍停留在有效 FitTracker 入口页。
12. 执行一次认证链路烟雾检查。

`tools/midscene-entrypoints-smoke.ps1` 目前按以下方式工作：

1. 检查 HDC 设备与 HAP 是否就绪。
2. 可选先执行 `-ResetAppData`，让真实执行从更干净的应用状态开始。
3. `current-plan`：尽快回到首页，断言当前启用预置计划入口存在，并从 `首页 -> 训练预览 -> 训练执行` 走完两步短链路。
4. `backup-card`：尽快回到首页，进入 `训练回顾`，滚动并断言 `数据备份` 卡。
5. `media-card`：尽快回到训练预览页，进入 `查看动作详情`，滚动并断言 `动作演示` 媒体卡。
6. `both`：串行跑完 `backup-card` 与 `media-card` 两个入口，但使用独立 run root，避免和全量回归抢摘要输出。

## 报告产物

- `midscene_run/full/<run-tag>/report/`：默认全量回归 HTML 报告与截图。
- `midscene_run/full/<run-tag>/log/`：默认全量回归运行日志。
- `midscene_run/full/<run-tag>/midscene-regression-summary.md`：默认全量回归摘要。
- `midscene_run/auth/<run-tag>/...`：默认认证回归产物。
- `midscene_run/focused/<target>-<run-tag>/...`：默认 focused smoke 产物。

如果传入 `-RunRoot`，以上产物都会写到指定目录；如果只传 `-RunTag`，脚本会在各自默认前缀下自动创建独立目录，尽量减少并行执行时的 summary/report 冲突。

每次真实执行后，都建议补充 `docs/midscene-regression-report-template.md`，把设备、命令、截图和结论整理完整。

## 失败排查

| 问题 | 处理 |
| --- | --- |
| `hdc` 找不到 | 检查 DevEco Studio toolchains 是否已加入 `PATH` |
| `hdc list targets` 为空 | 确认模拟器已启动并解锁 |
| `PackageHap -> spawn java ENOENT` | 先执行 `powershell -ExecutionPolicy Bypass -File tools/deveco-env.ps1`，再重跑 hvigor；该脚本会统一补齐 DevEco PATH 与 Java shim |
| Midscene 404 / `InvalidEndpointOrModel.NotFound` | 说明当前模型名或接入点不可用，切换到可访问的视觉模型 |
| Midscene 400 / `ChatCompletionRequestMultiContent can only support text` | 说明当前接入点不是可用的视觉模型，不能用于截图断言 |
| 断言失败 | 打开 `midscene_run/report/` 的最新 HTML 报告，查看截图和回放 |
| 进入了错误页面 | 先确认 `AppRoutes` 与 `main_pages.json` 一致，再重跑脚本 |
