## 1. 文档概述
本文档旨在定义 FitTracker 健身工具 App 的核心功能、交互逻辑、数据规则与非功能要求，指导设计、前端、后端及测试团队进行 MVP 及后续版本开发。文档将随项目迭代持续更新。

## 2. 产品概述

### 2.1 产品定位
面向大众健身爱好者的轻量级训练决策与记录工具。通过“内置训练计划 + 智能动作库 + 自动数据追踪”解决“不知道练什么”和“无法衡量进步”两大核心痛点，不涉及线上约课、社交、电商等重运营功能。

### 2.2 核心价值主张
- **即开即练**：预置科学训练计划，一键开始训练，免去决策负担。
- **一切皆可量化**：每次训练自动沉淀为结构化数据，形成个人能力档案。
- **进步可视**：关键力量指标的趋势图与训练热力图，将汗水转化为可感知的成长。

### 2.3 用户画像细化
- **小白爱好者（新手期<6个月）**：需要明确指导，依赖预置计划，渴望看到早期进步。
- **规律训练者（6个月~3年）**：了解自身分化，需要灵活自定义计划，注重容量与力量的阶段变化。
- **进阶训练者（3年+）**：周期化训练意识强，关注1RM变化、肌群训练频率均衡，愿主动管理动作库与个人纪录。

## 3. 功能需求详述

### 3.1 训练计划模块
**用户故事**：作为健身爱好者，我希望直接选用一套科学的分化训练计划，每天打开App就知道该练什么，无需纠结编排。

#### 3.1.1 功能描述
提供预置训练计划库，支持用户一键启用并按日推送训练动作清单。同时允许用户完全自定义创建计划，对计划内的训练日、动作组合、顺序进行增删改。

#### 3.1.2 用户操作流程
**流程A：选用预置计划**
1. 用户首次进入“训练”Tab，系统展示推荐计划列表（卡片形式，含计划名、简介、周频率）。
2. 点击计划卡片进入详情，预览所有训练日及对应动作列表（只读）。
3. 点击“开始此计划”按钮，系统将该计划克隆至“我的计划”并设为当前执行计划。
4. 首页/训练Tab自动变为“今日训练”视图，展示当天应练动作清单。
5. 训练日当天，用户点击“开始训练”进入训练记录流程（见3.3）；若当天无安排，提示“今日休息”并建议拉伸。

**流程B：自定义创建计划**
1. 在“我的计划”页点击“新建计划”。
2. 输入计划名称、选择训练日（如周一、周三、周五），设置周期为重复或指定周次。
3. 为每个训练日添加动作：从动作库搜索/筛选并勾选，拖拽排序或手动输入序号；可设定推荐组数/次数范围（非强制）。
4. 保存后，自定义计划同样出现在“我的计划”列表，可设为当前计划。

#### 3.1.3 页面元素与交互逻辑
- **计划列表页**：
  - 顶部分段控件“预置计划 | 我的计划”。
  - 预置计划卡片：封面图、名称、适用人群标签、时长/频率。
  - 我的计划列表：显示当前使用计划高亮标记，左划可删除，点击进入编辑。
- **计划详情/编辑页**：
  - 训练日列表以纵向时间线展示：日期/星期，下方为该日动作清单（动作名+目标肌群小标签）。
  - 编辑模式下，训练日可增删，动作可拖拽排序，点击动作可更换或移除。
- **今日训练主视图**（训练Tab首屏）：
  - 日期与欢迎语，若为训练日，展示当日训练动作列表（名称、预设组数×次数）。
  - 底部悬浮按钮“开始训练”。

### 3.2 动作库模块
**用户故事**：作为一名训练者，我想要查看标准动作演示并自动追踪自己的个人最好成绩，以便知晓自己的强项与弱项并安全训练。

#### 3.2.1 功能描述
建立中心化标准动作库（预置约200+常见动作），每个动作包含图文说明及演示占位。与用户绑定，系统自动记录每个动作的个人历史最高重量与次数（计算估算1RM），并支持按肌群、器械等多维筛选。

#### 3.2.2 用户操作流程
- **浏览动作库**：从训练Tab或独立入口进入动作库列表，支持通过搜索框、肌群筛选栏、器械标签快速定位。
- **查看动作详情**：点击动作进入详情页，展示示范图/视频位、文字要领、目标肌群解剖图、个人纪录区域（最佳1RM、最多次数、历史最佳重量×次数组）。
- **个人纪录自动更新**：任何一次训练记录完成后，系统比对本次该动作的单组最高重量/次数，若打破历史纪录则更新并提示“恭喜！新个人纪录！”。

#### 3.2.3 页面元素与交互
- **动作库列表页**：搜索框置顶；横向滑动机群筛选（胸、背、腿、肩、臂、腹），下方为器械类型标签（杠铃、哑铃、绳索、固定器械、自重）。列表以卡片展示，左侧动作小示意图，右侧动作名+主肌群。
- **动作详情页**：头部大图/视频占位（可播放）；切换标签“动作要领”“参与肌群”；下方“我的纪录”卡片，展示最佳1RM、最重一次组详情、纪录打破日期。若无纪录显示“尚未记录”。
- **个人纪录计算规则**：重量×次数使用Epley公式估算1RM（1RM = w × (1 + r/30)），记录最大值。纪录计算仅针对有重量的力量动作，自重动作仅记录最多次数。

### 3.3 训练记录与统计模块
**用户故事**：作为训练者，我希望轻松记录每组训练数据，并在日历与统计图中直观看到自己的训练频次、容量变化与力量成长。

#### 3.3.1 功能描述
提供一个轻量级的训练记录器，按计划动作逐组录入。数据自动汇入数据库，驱动日历热力图与多维统计面板。

#### 3.3.2 用户操作流程
**训练记录流程**：
1. 从“今日训练”页点击“开始训练”，启动计时器，进入记录模式。
2. 页面展示当日所有计划动作，完成一个动作点击展开组数录入器。
3. 组数录入：动态表单，每行一组，包含三个输入框：重量（kg/lbs，依据用户设置）、次数、完成程度（RPE/注释，可选）。下方按钮“添加组”。
4. 每组数据填写即自动保存草稿。中途切出可恢复。
5. 全部动作完成后，点击“结束训练”，汇总训练时长、总组数、总容量（重量×次数总和）。提示是否添加训练感受与备注。保存后生成一次训练记录。
6. 若用户临时添加未计划的动作，提供“添加动作”按钮，从动作库搜索插入。

**统计查看**：
- 日历视图：默认月视图，日期方块颜色深浅代表训练时长或总容量（可切换）。点击日期可弹出当天训练摘要卡片（肌群标签、时长、主要动作）。
- 统计面板：顶部切换周/月/年。展示总训练次数、总时长、各肌群训练次数占比环形图、关键动作（由用户标记或系统默认三大项）力量趋势折线图。

#### 3.3.3 页面元素与交互
- **记录器界面**：顶部计时器与扩展按钮（暂停、放弃）。动作列表以可折叠手风琴展示，完成进度（已填组数/计划组数）。每输入一组，左侧自动显示该组1RM估算，若刷新纪录输入框变金色闪光。
- **日历热力图**：点击“统计”Tab，日历显示在页面上半部，左右箭切换月份。日期块颜色分5档（无训练、短、中、长、极长），图例下方显示。
- **统计面板页**（统计Tab下半部/独立页面）：指标卡片横向滑动，力量趋势图可双指缩放时间窗，点击曲线散点显示具体训练日详情。

#### 3.3.5 交互逻辑补充（流程描述）
1. 用户点击“开始训练” → 创建session草稿状态，计时开始。
2. 录入每组数据 → 前端本地暂存，每录入一组调用后端接口实时保存该组（防止丢失）。
3. 用户结束训练 → 前端发送结束请求，后端计算总时长、总组数、总容量，并触发纪录比对服务（对比user_exercise_records，更新个人纪录）。
4. 成功返回后，弹出训练摘要并释放计时器，更新日历数据。

## 4. 非功能需求

### 4.1 性能要求
- 训练记录页面（含多组输入框）冷启动打开≤1.5秒，组数据保存响应≤200ms。
- 统计图表（年趋势）数据加载≤2秒。
- 动作库列表支持分页加载，每页20条，滚动无感加载。

### 4.2 数据安全与隐私
- 所有训练数据属于用户核心隐私，必须全链路 HTTPS 加密。
- 用户数据支持导出（JSON/CSV）及账户删除后物理删除。
- 认证采用OAuth2.0+JWT，支持手机号或Apple/Google登录。

### 4.3 兼容性
- 移动端优先：iOS 15+，Android 10+。
- 适配主流屏幕尺寸（375pt~428pt宽度），支持暗黑模式。
- 可能的Web版本可作为后续迭代，MVP仅移动端。

### 4.4 可用性
- 训练记录过程防误触，结束训练需二次确认。
- 网络中断时，训练记录支持离线暂存，恢复信号后自动同步，避免数据丢失。

## 5. 数据埋点与指标

### 5.1 核心业务指标（北极星）
- **训练完成率（日/周）**：完成训练用户数/计划内有训练安排的用户数。
- **周留存率**：安装后第7天仍活跃用户比例。
- **人均月训练天数**：反映产品习惯养成强度。

### 5.2 关键埋点事件
| 事件名 | 触发时机 | 属性 |
|--------|----------|------|
| plan_start | 用户开始一个预置或自定义计划 | plan_id, is_preset, plan_type |
| training_start | 点击“开始训练” | session_id, plan_id, day_id |
| set_log | 记录一组训练数据 | exercise_id, weight, reps |
| training_complete | 成功结束训练并保存 | session_id, duration, total_volume |
| record_break | 打破个人纪录 | exercise_id, new_1rm, old_1rm |
| calendar_view | 查看日历视图 | view_type(month/week) |
| stat_view | 查看统计面板 | duration_selected |

## 6. 技术建议

### 6.1 后端技术栈建议
- API采用RESTful，MVP可使用Firebase/Supabase加速，后续迁移至Node.js/Go微服务。
- 数据库：PostgreSQL（结构化训练数据），Redis用于会话缓存及排行榜临时数据（未来）。

### 6.2 数据库概要设计
除前文核心表外，建议设计：

**用户表（users）**：id, phone, email, password_hash, units(metric/imperial), created_at  
**用户设置表（user_settings）**：user_id, preferred_unit, is_dark_mode, rest_timer  
**训练计划与动作库相关表如前所述。**  
**索引建议**：  
- workout_sessions表在（user_id, created_at）上建联合索引，优化日历查询。
- workout_sets在（session_id）及（exercise_id, user_id通过session关联）上适当索引以支持趋势图查询。

### 6.3 个人纪录更新机制
采用数据库事务+乐观锁：完成训练后，后端聚合本次所有动作的最佳组，与user_exercise_records比较，若突破则更新。可异步处理，避免训练保存接口阻塞。

### 6.4 文件存储
动作示范图片/视频使用云存储（如AWSS S3/Cloud Storage），CDN加速，访问URL填入exercises.media字段。

## 7. 版本规划

### 7.1 MVP 功能范围（V1.0）
- **训练计划模块**：预置5套计划（五分化、上下分化、推拉腿、全身3x、力量举基础），支持一键启用及按日推送。不支持自定义计划。
- **动作库模块**：内置150个标准动作，包含名称、目标肌群、图片占位、动作描述。按肌群筛选。用户个人纪录自动更新提示。
- **训练记录**：按计划动作进行组数记录，计时器，结束训练保存。无离线暂存。
- **统计**：日历视图（月）热力图，基础统计（周训练次数、总时长）。
- **账户系统**：手机号注册登录，基本资料设置。

### 7.2 后续迭代方向
- **V1.1**：自定义训练计划、动作库自定义增删动作（用户自定义动作）、训练笔记与RPE详细录入。
- **V1.2**：力量趋势图（三大项），肌群训练频率环形图，日历可点击查看详情。数据导出功能。
- **V1.3**：训练容量自动调节建议、休息计时器、组间倒计时。训练提醒推送。
- **V1.4**：社交轻功能（好友训练动态仅可见完成打卡，不涉及详细数据）、成就徽章系统。
- **V2.0**：AI训练推荐（基于历史数据与目标）、智能周期化计划生成。
