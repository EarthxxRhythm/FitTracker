# 外部健身数据源评估

> **日期：** 2026-10-16
> **核验方式：** 逐源实测（GitHub/Gitee API 取元数据、抓 LICENSE 与 README 原文、拉取真实数据集），非训练记忆转述
> **用途：** 为动作库扩充提供许可合规的数据源清单；菲特只采用许可明确允许商用的源
> **相关：** [动作/视频自建数据库方案](./动作视频自建数据库方案.md) · [内容导入说明](./内容导入说明.md)

## 1. 结论速览

| 判定 | 数据源 | 理由 |
| --- | --- | --- |
| ✅ **采用** | yuhonas/free-exercise-db | Unlicense（公共领域），873 条动作，无署名/copyleft/再分发义务 |
| ✅ 备用 | wrkout/exercises.json | 同上（free-exercise-db 的上游），许可同为 Unlicense |
| ⚠️ 有条件 | RepDB/exercise-dataset | 643 动作，免费层允许商用 in-app，但**必须署名**且**禁止再分发数据集**（team 3） |
| ⚠️ 有条件 | wger-project/wger | 932 动作，数据 CC-BY-SA（copyleft）——衍生数据库需同许可开放 |
| ⚠️ 有条件 | bryllim/workout-guide | 302 动作，图片 CC BY-SA 4.0（源自 Everkinetic） |
| ❌ 不采用 | hasaneyldrm/exercises-dataset 及其中文 fork | 媒体无授权 + 上游许可链矛盾（详见 §4） |
| ❌ 不采用 | ExerciseDB/exercisedb-api | 商用付费授权（11,000+ 动作） |
| ❌ 不采用 | Kaggle `gym-exercise-data` 等 | 许可标注混杂，需逐条核查，性价比低 |

**核心结论：** 唯一零摩擦源是 **free-exercise-db**（Unlicense 公共领域）。含中文的源恰是许可链最不干净的——**未找到「许可干净 + 商用可用 + 含中文」的动作数据源**，因此中文名与步骤说明由项目自行翻译/编写。

### 数据获取通路（实测）

GitHub 直连在本机被 TLS 阻断（`curl` exit 35），改用 **Gitee 镜像 + Gitee API** 成功取得全量数据：

```text
镜像仓库：https://gitee.com/kaiji1126/free-exercise-db   （yuhonas 的镜像，作者 Clint Plummer = yuhonas）
API 端点：https://gitee.com/api/v5/repos/kaiji1126/free-exercise-db/contents/dist/exercises.json
返回：JSON，content 字段为 base64 编码的 1,001,472 字节 → 解码后 873 条记录
```

## 3. 有条件源的许可约束

### RepDB（643 动作，EN/DE/ES）

`LICENSE-DATA.md` 实测原文：

1. 免费层允许**个人与商业**用途，在应用内使用；
2. **必须署名**：在 App 的关于/鸣谢页或 README/页脚放可见链接「Exercise data by RepDB (repdb.co)」；
3. **禁止再分发数据集**：不得把数据集（或其修改/衍生版本）作为数据集、数据集仓库或 API 重新发布；
4. 图片可缩放/裁剪/调色，但升级或去背景的衍生版本同受 term 3 约束；
5. 禁止生成式 AI 衍生。

**对本项目的含义**：可用于 App 内展示，但**不能**进入 `content/exercises/*.jsonl`（该文件是随 App 分发的数据，会构成"再分发数据集"）。若采用，须走运行时拉取或独立资源包，且需在设置页加署名。

### wger（932 动作）

- 软件许可 AGPL-3.0；**动作数据 CC-BY-SA 3.0/4.0**（API 每条记录带 `license` 字段，实测可见 `CC-BY-SA 4`）。
- 语言表含 `zh`（id=24），但实测 `exercise/?language=24` 返回 `count=932`，与不加语言过滤的计数相同——**语言过滤疑似未生效，中文覆盖率未确认**（待验证假设）。
- copyleft 含义：若把数据合并进本项目数据库，衍生数据库需以同许可开放。

### bryllim/workout-guide（302 动作）

- README 原文：代码 MIT；**视觉素材 CC BY-SA 4.0**，源自 [Everkinetic](https://github.com/everkinetic/data)。
- SVG 透明图，但 CC BY-SA 4.0 的 share-alike 条款对商用 App 有传染性约束。

## 4. 已排除源的风险证据

### hasaneyldrm/exercises-dataset（1,324 动作，含中文）

三重问题：

1. **媒体无授权**——LICENSE 原文：「It DOES NOT cover the exercise media in the `images/` and `videos/` directories… **Cloning this repository does not grant you any license to the media**; obtain your own from Gym visual.」
2. **许可声明互相矛盾**——GitHub LICENSE 为 MIT（仅覆盖文本/结构），而中文介绍文章明确写「仅限教育与非商业研究用途」。
3. **上游链条不清**——数据来源指向 ExerciseDB（一个商用授权产品）。

中文 fork（`wangmuerxiao/exercises-dataset-zh`）LICENSE 与上游字节相同，继承全部问题。

### ExerciseDB（11,000+）

商用付费授权产品（RapidAPI / exercisedb.io）。免费层范围与条款不满足本项目"可离线打包、可商用"的需求。

## 5. 对项目的落地含义

1. **采用 free-exercise-db 的文本数据**（动作名、肌群、器械、难度、步骤说明），由项目自行翻译为中文并补 `cues` / `commonMistakes` / `safetyNotes`（外部源无这些字段）。
2. **不引入任何外部媒体**——保持现有自制 GIF 方案与 `local://` 路径约定（校验器强制，见 `tools/content/build-content.mjs` 的 `validateLocalMediaField`）。
3. **中文覆盖需自行解决**——所有候选动作的 `nameZh` 与 `steps` 由人工/翻译补全后，方可进入内容管线。
4. **不要使用 RepDB/wger/workout-guide**，除非接受其署名、copyleft 或"不入库"约束（三者都与现有 JSONL 打包模式冲突）。
