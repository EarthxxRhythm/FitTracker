# FitTracker 项目重新初始化方案

版本：V1.0  
日期：2026-05-23

## 1. 初始化目标

将 FitTracker 从现有“训练计划 + 记录 + 统计”结构，重建为“目标配置 -> 计划生成 -> 训练执行 -> 训练复盘 -> 下次调整”的目标训练闭环架构。

本方案不要求立即删除旧代码。旧代码作为参考，主要用于复用以下经验：

- 本地 Preferences 存储。
- 训练记录数据结构。
- 1RM 计算逻辑。
- 统计页基础指标。
- ArkTS 严格模式修复经验。
- DesignTokens 和基础组件思路。

## 2. 初始化范围

### 2.1 第一阶段包含

- 新建 feature-first 目录结构。
- 新建共享模型目录。
- 新建服务接口和空实现。
- 新建 seed/mock 内容结构。
- 新建五个核心 Tab 占位页。
- 新建目标问卷占位页。
- 新建路由注册。
- 新建本地内容和用户数据 store 命名。
- 保留旧页面，直到新路由可以替代。

### 2.2 第一阶段不包含

- 删除旧业务代码。
- 完整迁移所有功能。
- 接入自建后台。
- 接入真实视频内容。
- 建设内容管理后台。
- 接入 MuscleWiki 官方 API。

## 5. 数据初始化清单

### 5.1 内容 seed

- 肌群：胸、背、腿、肩、手臂、核心。
- 器械：杠铃、哑铃、绳索、固定器械、自重、弹力带。
- 动作：每个主要肌群至少 5 个动作。
- 动作字段：名称、英文名、主要肌群、次要肌群、器械、难度、目标标签、步骤、要领、常见错误、安全提示、替代动作。
- 计划规则：按目标、训练水平、天数、器械生成。

### 5.2 用户数据 store

- `fit_tracker_goal`
- `fit_tracker_content`
- `fit_tracker_plans`
- `fit_tracker_workouts`
- `fit_tracker_records`

## 6. 服务初始化清单

| 服务 | 第一阶段职责 |
| --- | --- |
| ContentRepository | 从 seed 返回动作、肌群、器械和替代动作 |
| PlanEngine | 根据目标生成简单计划 |
| GoalRepository | 保存和读取目标配置 |
| WorkoutRepository | 保存训练草稿和训练记录 |
| ReviewService | 计算容量、1RM、完成率 |
| SyncService | 返回本地内容版本和占位同步状态 |

## 7. 迁移策略

1. 先提交文档和初始化方案。
2. 新建骨架，不删除旧页面。
3. 新首页跑通后再替换启动路由。
4. 训练记录功能重写完成后，再迁移旧记录服务逻辑。
5. 统计复盘完成后，再替换旧 StatsPage。
6. 所有新页面可编译后，再清理旧页面和旧路由。

## 8. 风险控制

- 每次只替换一个主流程节点。
- 每个服务先写测试或最小验证脚本。
- 不在同一提交中同时做目录迁移和复杂逻辑迁移。
- 不使用 `git reset --hard` 或批量删除旧文件。
- 不创建真实后台依赖，后台调用先通过接口和 mock 约束。

## 9. 完成标准

第一阶段完成后应满足：

- 新目录结构存在。
- 新页面均可被路由注册。
- seed 数据可被 `ContentRepository` 读取。
- `PlanEngine` 可生成最小计划。
- 训练记录可本地保存一条 session。
- 文档、PRD、原型说明和代码规范保持一致。
