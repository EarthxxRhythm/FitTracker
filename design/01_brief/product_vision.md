# FitTracker Product Vision

## What FitTracker Is
FitTracker is a **HarmonyOS local-first, goal-driven training assistant**. It is not a generic fitness content feed, not a social product, and not a marketing-heavy lifestyle surface. It should feel like a **trusted personal training system** that helps the user decide what to train, record what happened, and understand whether progress is real.

## Core User Promise
A user should be able to open the app and quickly answer three questions:

1. **What should I train today?**
2. **How do I record it efficiently?**
3. **Am I actually improving over time?**

If the app cannot answer those three questions clearly, the product is off-track.

## Product Positioning
FitTracker should occupy the space between:
- a consumer workout tracker
- a structured training log
- a high-end personal performance dashboard

It should feel more serious and more trustworthy than a typical fitness app, but more usable and more personal than a pure analytics dashboard.

## Non-Negotiable Product Principles

### 1. Local-first
The core training flow must work without:
- a backend
- an account system
- cloud sync
- an external exercise API

### 2. Goal-driven
The product starts from the user’s training goal, not from a generic exercise catalog.
The app should continuously reinforce the sense that the plan, preview, execution, and review screens are all connected to the user’s goal.

### 3. Data trust
The user must be able to trust that:
- sessions are saved correctly
- warmup sets and working sets are interpreted correctly
- PRs are real
- trends and weekly stats reflect actual history

### 4. UX clarity over feature noise
FitTracker should not overwhelm users with too many equal-weight surfaces. The app should always have a **clear primary action**, especially on the Home page and Active Workout page.

### 5. Professional but not cold
The product should feel refined, deliberate, and premium. It should not feel like:
- a generic dark-mode utility
- a gaming HUD
- a sports drink ad
- a medical device UI

## Core User Journey
The app must support a stable and understandable flow:

**Goal Setup → Home → Workout Preview → Active Workout → Workout Summary → Review → Goal Adjustment**

Each step should feel like part of one continuous training system, not separate mini-apps.

## What “Good” Looks Like
A strong FitTracker build should create these impressions:
- The user knows what matters immediately.
- The interface helps action, not just display.
- The product feels designed, not assembled.
- Data looks meaningful and trustworthy.
- The user feels guided, not marketed to.

## What FitTracker Is Not
FitTracker should not become:
- a content-first exercise encyclopedia
- a social fitness community
- a generic wellness lifestyle app
- a flashy futuristic concept UI
- a cluttered dashboard with too many equally loud widgets

## Design and Engineering Implication
Any new UI, UX, or visual decision should be judged by one question:

> Does this make FitTracker feel more like a premium, trustworthy training system?

If not, it should be simplified, removed, or redesigned.
