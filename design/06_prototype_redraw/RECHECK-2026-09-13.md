## 三、发现

1. **home / preview 已达标**（align 35 口径，与既有工具默认一致）：4.16% / 3.59%。

2. **plan 未达标，且对齐不是原因。** align 扫描：
   `0→10.93%`、`20→11.82%`、`28→11.42%`、`30→11.80%`、`32→12.03%`、`35→12.29%`、`40→13.04%`、`48→14.92%`。
   **最优在 0 且仍 >8%**，说明差异来自真实内容差（还原缺陷或数据差），须按 H1–H7 展开诊断，不能靠调 align 消除。

3. **各屏最优 align 不一致再次被证实**：home/preview 在 35，plan 在 0。单一全局 align 无法同时适用，与 `ACCEPTANCE-PLAN.md` 的偏移扫描结论一致。**逐屏应记录 best-fit 与物理对齐两组数字。**

4. **数据差现场确认**：home 的「动作数 0 / 预计用时 0 / 目标肌群 0 / 进度环 0%」与原型静态示例（8 / 60 / 3 / 14%）不同，系 `DeviceSeedService.applyTodayFlowSeed` 只写 goal、不生成当日动作安排所致（非还原缺陷）。preview 屏反有数据（2 个动作：哑铃卧推 / 俯卧撑，各 3×8-12）。

5. **bundleName 变更的连带已验证可解**：新沙箱下 seed 机制工作正常，splash 按 `devSeed` 直达 home；设备上旧包 `com.example.fittracker_opencode` 仍在（与新包共存），后续可卸载。

### 6.1 最优 align 强烈分屏（重要口径结论）

| 最优 align | 屏 |
|---|---|
| **0** | welcome、plan、library |
| **35** | home、preview、settings、body、profile、login、register、review |

**不存在单一通用 align。** 用 35 去量 welcome 会得到 12.71%（伪差），用 0 去量 home 会得到 10.45%。逐屏必须记录 best-fit 与物理对齐两组数字——这是本轮最重要的方法论结论，与 `ACCEPTANCE-PLAN.md` 的偏移扫描结论一致。

### 6.2 library 的口径说明（不静默）

28.42% 是**未掩蔽**结果。该屏含 3 个 Grid、每张卡片内嵌 GIF 缩略图（如 `Column#lib-card-barbell-row` 内的 `Column [719,824,821,926] clickable`），动画帧不同步会产生大面积伪差——与 `ACCEPTANCE-PLAN.md` 已登记的「动画媒体屏须先冻结或掩蔽」同因。**该数字不得当作还原缺陷结论**；须按 `--ignore-rect` 掩蔽各卡片媒体区后复测。

### 6.3 review 的数据差已排除

本轮 review 使用 **`review_metrics` seed**（有数据：「本周 · 9月7日–9月13日」），仍有 12.33%，说明除已知的数据差外**还存在真实差异**，需按 H1–H7 展开，不能再用「数据差」解释。
